# Task 7.1a — Core Identity, `StatusThresholds`, `MetricSource`, & `ThermalSensorClassifier`

**Phase:** 7 — Widget & Popover Redesign (Sub-phase 7A: Architecture & Core Domain)
**Depends on:** 7.0
**Blocks:** 7.1b, 7.2a, 7.4a–h

## What to do

1. **Step 7.1a.1 — Add canonical `symbolName` to `MetricCategory` (`Sources/iStatsCore/MetricCategory.swift`):**
   - Add `public func symbolName(hasBattery: Bool = true) -> String` (and convenience `public var symbolName: String` defaulting `hasBattery: true`):
     - `.cpu` → `"cpu"`
     - `.memory` → `"memorychip"`
     - `.gpu` → `"square.3.layers.3d"`
     - `.thermal` → `"thermometer.medium"`
     - `.fan` → `"fan"`
     - `.network` → `"arrow.up.arrow.down"`
     - `.disk` → `"internaldrive"`
     - `.power` → `hasBattery ? "battery.100percent.bolt" : "powerplug.fill"`
   - Add `public var shortLabel: String` (`"CPU"`, `"MEM"`, `"GPU"`, `"TMP"`, `"FAN"`, `"NET"`, `"SSD"`, `"BAT"` / `"PWR"`) for 3-letter vertical widget labels.
2. **Step 7.1a.2 — Create `MetricSource` & `ThermalSensorClassifier` (`Sources/iStatsCore/ThermalSensorClassifier.swift`):**
   - Define `public enum MetricSource: String, Codable, CaseIterable, Identifiable, Sendable`:
     - `.peak`, `.cpu`, `.gpu`, `.memory`, `.ssd`, `.battery`
     - Include `displayName`, `shortLabel` (`"TMP"`, `"CPU"`, `"GPU"`, `"MEM"`, `"SSD"`, `"BAT"`), and `symbolName`.
   - Implement `public enum ThermalSensorClassifier` with pure methods:
     - `classify(_ sensor: SensorReading) -> MetricSource?` (matching CPU/Efficiency/Performance/SoC/Package, GPU, Memory/RAM, Storage/NAND/SSD, Battery)
     - `sensors(in sample: ThermalSample, for source: MetricSource) -> [SensorReading]`
     - `peakCelsius(in sample: ThermalSample, for source: MetricSource) -> Double?`
3. **Step 7.1a.3 — Create `StatusThresholds` (`Sources/iStatsCore/StatusThresholds.swift`):**
   - Move/unify `CoreStatusLevel` (or `StatusSeverity: String, Codable, Sendable, Comparable` with `.fine`, `.elevated`, `.warning`, `.critical`) in `iStatsCore`.
   - Define a single tested threshold table for:
     - `cpu(usagePercent: Double)` (e.g. elevated ≥ 25%, warning ≥ 65%, critical ≥ 90%)
     - `memory(pressure: MemoryPressure, swapUsedBytes: UInt64)` (driven by `MemoryPressure`, not used %)
     - `gpu(utilizationPercent: Double)` (elevated ≥ 50%, warning ≥ 75%, critical ≥ 92%)
     - `temperature(celsius: Double, source: MetricSource, pressure: ThermalPressure?)` (incorporates both `ThermalPressure` and per-source °C cut-offs: e.g. battery/SSD lower than CPU/GPU)
     - `fan(rpm: Double, minRPM: Double, maxRPM: Double)` (elevated ≥ 50% span, warning ≥ 80%, critical ≥ 95%)
     - `disk(usedPercent: Double)` (elevated ≥ 80%, warning ≥ 90%, critical ≥ 95%)
     - `battery(chargePercent: Double, isCharging: Bool, powerDeficitWatts: Double?)` (warning ≤ 20%, critical ≤ 10%, or elevated/warning when discharging on AC adapter)
4. **Step 7.1a.4 — Write unit tests in `Tests/iStatsCoreTests/`:**
   - Extend `MetricCategoryTests.swift` for `symbolName` and `shortLabel`.
   - Add `StatusThresholdsTests.swift` covering boundary values for every category and `MetricSource`.
   - Add `ThermalSensorClassifierTests.swift` covering sensor classification and peak extraction.
