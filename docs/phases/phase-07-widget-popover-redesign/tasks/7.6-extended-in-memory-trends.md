# Task 7.6 *(Optional)* — Extended In-Memory Trends (`5m | 15m` Scalar Buffers)

**Phase:** 7 — Widget & Popover Redesign (Sub-phase 7F: Shared History & Optional Extensions)
**Depends on:** 7.5
**Blocks:** 7.7 (if included in Phase 7 scope per Task 7.0)

## What to do

1. **Step 7.6.1 — Add lightweight scalar series buffers in `iStatsCore` (`MetricsStore.swift`):**
   - Keep full `Sample<T>` ring buffers at capacity `60` so full-struct memory footprint does not grow.
   - Add compact scalar ring buffers (`RingBuffer<ScalarPoint>`, capacity `900` = 15 minutes at 1 s or 30 minutes at 2 s) for the chartable series of each category.
   - Strictly in-memory only — zero disk persistence (ADR 0006).
2. **Step 7.6.2 — Add pure bucket downsampling for display:**
   - Implement a pure downsampler (e.g. LTTB or max-preserving bucket downsampler to ≤ 120 display points) in `iStatsCore` so rendering 5m / 15m charts in `TrendChart` costs the same CPU/GPU time as 1m charts while preserving spikes.
3. **Step 7.6.3 — Enable `5m | 15m` range picker in `HistoryTab.swift`:**
   - Bind the range picker in `HistoryTab` to slice and downsample the scalar series buffer for the selected time window.
4. **Step 7.6.4 — Measure memory overhead & add unit tests:**
   - Extend `RingBufferTests.swift` and `MetricsStoreTests.swift` for scalar retention and spike-preserving downsampling.
   - Record the measured byte footprint of the 900-point buffers in `docs/phases/phase-07-widget-popover-redesign/report.md`.
