# Task 8.8h — Power Panel: Battery Glyph + Power Flow

**Phase:** 8 (Sub-phase 8C) · **Depends on:** 8.6 · **Blueprint:** [`design.md §6.8`](../design.md)

## What to do
1. **Step 8.8h.1 — `PowerFlowMath` (iStatsCore, pure):** given `adapterWatts`, `powerDrawWatts`, `voltageVolts`, `amperageMilliAmps`, `state`, return edges `{adapterToMac, adapterToBattery, batteryToMac}` in watts (each `nil` when not derivable) and a particle speed per edge (`speed = clamp(log1p(W)/log1p(100), 0.1, 1)`). Battery net W = V × A / 1000 with sign from amperage. Never invent the adapter split: if it can't be derived, show only the edges that can. Tests cover charging, discharging, on-hold, deficit, missing V/A, and desktop.
2. **Step 8.8h.2 — Glance:** battery Macs: `charge` %; desktop: system watts. Headline via `PanelHeadline.power` ("Charging · full in 42 m"). Chart = charge % or watts.
3. **Step 8.8h.3 — Now (battery):**
   - *Battery glyph:* 88×40 custom shape (body + nub), fill width = charge, Power tint gradient; at low charge the fill uses status colours; when charging, a shimmer sweep (`MotionPolicy.full` only) + bolt symbol.
   - *Power Flow:* 3 nodes (Adapter · Mac · Battery) with `LiveNumber` watts, edges as curved paths, particles along paths via `TimelineView` + `Canvas` at the `PowerFlowMath` speed. Reduce Motion: static arrows + watt labels. `onHold` / `powerDeficit` → edge colour + ribbon.
   - Time remaining row (hidden when `nil`).
4. **Step 8.8h.4 — Detail (Health):** `RingStack` health % (`healthPercentage`); cycles `Meter` (`cycleCount / designCycleCount`); condition; design vs max capacity; adapter name.
5. **Step 8.8h.5 — Desktop:** draw `ArcGauge` + adapter info; 2 pages (Now, History) as in `PopoverTab.supportedTabs(for: .power, hasBattery: false)`.
6. **Previews:** charging, discharging, on hold, deficit, low battery, desktop, unavailable.
