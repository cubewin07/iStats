# Task 8.2 — Motion System & `LiveNumber`

**Phase:** 8 (Sub-phase 8A) · **Depends on:** 8.1 · **Blocks:** 8.4, 8.5, 8.6

## Purpose
Make values feel alive: rolling digits, eased meters, and one place that decides when motion is allowed.

## What to do
1. **Step 8.2.1 — `iStats/UI/Instrument/Motion.swift`:** the `Motion` tokens from [`design.md §5`](../design.md) (`snappy`, `smooth`, `value(interval:)`, `panelIn/Out`, `pulse`). `Motion.value(interval:)` comes from a pure helper `MotionMath.valueDuration(interval:)` = `min(0.6, interval × 0.6)`. Put `MotionMath` in `iStatsCore` and test it.
2. **Step 8.2.2 — `MotionPolicy` environment value:** `.full`, `.reduced`, or `.frozen`, computed from `accessibilityReduceMotion`, `coordinator.isLowPowerModeActive`, `preferences.isSamplingPaused`, and panel visibility. Inject it at the scaffold root. Every animated component reads it, so no component checks the system flags itself. The pure resolver `MotionPolicy.resolve(reduceMotion:lowPower:paused:visible:)` lives in core and is tested.
3. **Step 8.2.3 — `LiveNumber` view:** inputs `value: Double`, `format: (Double) -> String`, `font`, `unit`. On macOS 14+ with policy `.full` it uses `.contentTransition(.numericText(value:))` + `Motion.value`. Otherwise it uses a 150 ms crossfade. Always tabular digits. It reports `accessibilityValue` as the formatted string.
4. **Step 8.2.4 — `easedProgress` modifier:** wraps a 0…1 value with `Motion.value` animation under `.full`, or instant under `.frozen`. Meters/gauges use it in 8.5.

## Files
`iStats/UI/Instrument/Motion.swift`, `iStats/UI/Instrument/LiveNumber.swift`, `Sources/iStatsCore/MotionMath.swift` (+ `MotionPolicy` resolver), `Tests/iStatsCoreTests/MotionMathTests.swift`.

## Definition of done
- `swift test --scratch-path /tmp/istats-build --filter MotionMathTests` passes. Previews show `LiveNumber` stepping through values under all three policies.
