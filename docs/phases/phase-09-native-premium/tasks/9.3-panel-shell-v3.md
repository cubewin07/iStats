# Task 9.3 — Panel Shell v3 (header strip, slim footer, destinations)

**Phase:** 9 (Stage B) · **Depends on:** 9.1, 9.2 · **Blocks:** 9.4 to 9.6 · **Rules:** 1, 2

## Intent
Replace the 28 pt "eyebrow" row (badge, title, `PageSwitcher`, ellipsis menu, pin, close) with a header strip (identity + status + pin/close) and a 24 pt footer (page switcher, pause, settings). Introduce `PanelDestination` (`.overview` or `.category`) so the panel can show an Overview as well as a category, and give the shell a complete keyboard map. This reverses the footer removal of ADR 0009 (see ADR 0011).

## Approach
1. **Core.** `Sources/iStatsCore/PanelDestination.swift`: `enum PanelDestination: Hashable, Sendable { case overview; case category(MetricCategory) }` with `storageKey` (`"overview"` or category `rawValue`), `init?(storageKey:)`, `neighbor(offset:in: [MetricCategory])` for cycling (Overview first, then categories in the active order).
2. **Chrome.** `PanelChrome` (new, in `PanelScaffold.swift` or `iStats/UI/Panels/PanelChrome.swift`): `PanelHeaderStrip` (identity symbol + `CategoryIdentity.displayName`, status chip, pin, close; 28 pt, 10 pt eyebrow type) and `PanelFooterBar` (24 pt: `PageSwitcher` left, pause/resume + settings gear right). `PanelGlance` stays as the glance data model; `PanelScaffold` composes `PanelChrome` around content. Remove `eyebrowRow` and the ellipsis menu; keep Pin and Close in the header.
3. **Destination plumbing.** `PanelController.pinnedPanels` becomes keyed by `PanelDestination`; `swapToCategory` becomes `swap(to: PanelDestination)` (keep a thin `swapToCategory` wrapper for current callers); `PanelFactory.makePanelView(destination:...)` returns `OverviewView` placeholder until 9.4. `MetricPanel` gets `destination` and keeps `category` as a computed shim. Last destination persists via `lastPanelDestination` (9.2).
4. **Keyboard map.** `MetricPanel.keyDown`: Esc close; Cmd+W close; Cmd+, settings; Cmd+P pin; Space pause; Left/Right previous/next destination; Cmd+1/2/3 page (Now/Details/History); `[` / `]` history range; `?` opens glossary (stub until 9.11). Document the map in `design.md` keyboard table.
5. **Focus and VoiceOver.** Header and footer get accessibility labels; `accessibilityElement(children: .contain)` per region; footer buttons reachable by Tab.

## Acceptance criteria
- Every panel shows the header strip and footer; max height 560 still holds; no content clipping at small heights.
- Left/Right cycles destinations; Overview reachable; keyboard map matches docs.
- Existing hover-swap, pin, unpin and transient-close flows behave as before (lifecycle tests green).

## Risks
- `PanelController` rekeying breaks pinned panels: keep `swapToCategory` wrapper, extend tests first.
- Footer eats 24 pt: re-check `measureHeight` and the 560 cap on CPU and Network.
- Key handling with SwiftUI focus: the pure command mapping keeps behaviour testable.

## Out of scope
Overview contents (9.4), per-page content (9.5, 9.6), glossary sheet (9.11), Settings (9.9).
