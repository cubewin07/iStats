# Task 9.2 — Preferences Model v2 and Migration (core, no UI)

**Phase:** 9 (Stage A) · **Depends on:** 9.1 · **Blocks:** 9.3, 9.8, 9.9, 9.10, 9.11

## Intent
Add a versioned, idempotent preferences migration; introduce `AlertRule` and the new keys; fix the tab-memory scope; remove dead state; and key pinned origins by destination, with no data loss for existing users.

## Current code (`Sources/iStatsCore/PreferencesStore.swift`)
- `Keys` enum and `@Published` properties for 15 scattered alert keys (`cpuAlertEnabled`/`cpuAlertThreshold`, `memoryAlert*`, `batteryLow*`, `batteryFullAlertEnabled`, `thermalAlert*`, `diskAlert*`, `alertCooldownInterval`), read by `iStats/App/AlertCoordinator.swift:198-266` and `iStats/UI/PreferencesAlertsPane.swift`.
- Dead state: `menuBarDisplayMode` + nested `PreferencesStore.MenuBarDisplayMode` (observed in `MenuBarController.swift` only as a sync trigger; `MenuBarController.formatTitle/formatToolTip` and their tests in `Tests/iStatsTests/DetailViewGraphsTests.swift:88-103` and `MenuBarDisplayTests.swift`); `widgetPopoverStyles`, `PopoverStyle` (28 cases, `MenuBarItemConfig.swift:186`), `item.popoverStyle`, `resolvedPopoverStyle(...)`; unused helpers `isItemEnabled`, `toggleItem`, `updateItemOptions`, `toggleCategory`, `setSamplingPaused`, `toggleSamplingPaused`.
- Tab memory: `categoryLastTabs` (store) vs per-item `PopoverConfig.rememberLastTab` (`PopoverConfig.swift:46`, `MenuBarItemConfig.swift:484`, `PanelFactory.makePanelView`, `PreferencesMenuBarPane.swift:691`).
- `pinnedPanelOrigins: [String: [Double]]` keyed by `MetricCategory.rawValue`; `pinnedOrigin(for:)` / `setPinnedOrigin(_:for:)` are **live** (`PanelController.swift:343,353`, `PanelControllerLifecycleTests.swift:300`).
- `init(userDefaults:)` already injectable (tests use suites); `resetToDefaults()` lists every key.

## Approach
1. **Migration.** `Sources/iStatsCore/PreferencesMigration.swift`: `PreferencesMigration.currentVersion = 2`, `migrate(defaults:) -> Result`. Reads `preferencesSchemaVersion` (absent = v1). v1 to v2: write `AlertRule`s from the 15 legacy keys (keep legacy keys readable until 9.10 removes them), set `hasCompletedOnboarding = true` if any legacy key exists (existing user), map `categoryLastTabs`, drop `widgetPopoverStyles` and `menuBarDisplayMode`. Unknown values are preserved. Running twice is a no-op. Called at the top of `PreferencesStore.init`.
2. **`AlertRule`.** `Sources/iStatsCore/AlertRule.swift`: `Codable, Hashable, Sendable` with `kind: AlertKind` (cpu, memory, battery low, battery full, temperature, disk), `enabled`, `threshold`, `comparison` (`above`/`below`), `sustainSeconds`, `cooldownSeconds`, optional `target` (volume path or interface). Store holds `alertRules: [AlertRule]`.
3. **New keys/properties:** `lastPanelDestination` (stores `PanelDestination.storageKey`, string until 9.3 adds the enum), `lastSettingsSection` (string), `hasCompletedOnboarding`, `menuBarAppearance` (`MenuBarAppearance` enum `.monochrome/.statusTint/.categoryColor`, default `.statusTint`), `networkInterfaceSelection` (`String?`).
4. **Tab scope.** Keep `categoryLastTabs`; make `PanelFactory` always use it; keep decoding `PopoverConfig.rememberLastTab` (ignored) so old data decodes, stop encoding it.
5. **Dead state removal.** Delete `MenuBarDisplayMode`, `menuBarDisplayMode`, `MenuBarController.formatTitle/formatToolTip` (and their tests), `widgetPopoverStyles`, `PopoverStyle` and `popoverStyle` resolution, unused Store helpers; update `resetToDefaults()`.
6. **Pinned origins.** Add `pinnedOrigin(forDestinationKey:)` / `setPinnedOrigin(_:forDestinationKey:)`; `storageKey` is `"overview"` or the category raw value, so existing entries remain valid. Keep the category overloads as wrappers.

## Acceptance criteria
- Fresh and migrated stores expose the new keys with documented defaults; migration idempotent; widget layout and thresholds of a v1 profile are preserved.
- No references remain to `MenuBarDisplayMode`, `formatTitle`, `widgetPopoverStyles`, `PopoverStyle`.

## Risks
- Wiping a user's widget layout: fixture-first, keep unknown values, never delete `menuBarItems`.
- Removing `PopoverStyle` ripples into `MenuBarItemConfig` decode (`popoverStyle` field): keep tolerant decoding.

## Out of scope
Any UI; the `AlertEvaluator` (9.10); `PanelDestination` enum (9.3).
