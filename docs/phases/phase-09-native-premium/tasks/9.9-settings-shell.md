# Task 9.9 — Settings Shell (NavigationSplitView, single window path)

**Phase:** 9 (Stage D) · **Depends on:** 9.2 · **Blocks:** 9.10, 9.11

## Intent
Replace the tabbed preferences window with a sidebar Settings window (General, Menu Bar, one section per category, Alerts, About), with one way to open it (from the panel footer, Cmd+, and the status item context menu) and the last section remembered.

## Current code
- `iStats/App/PreferencesWindowController.swift` (window creation), `iStats/App/iStatsApp.swift` (Settings scene / app delegate wiring; excluded from SwiftPM), `iStats/UI/PreferencesView.swift` (tab container), `PreferencesGeneralPane`-style files, `PreferencesMenuBarPane.swift`, `PreferencesAlertsPane.swift`, `PreferencesComponents.swift` (`preferenceCategoryIcon` at line 196).
- Open paths today: `MenuBarController.showContextMenu` (519), the panel menu "Settings..." (removed in 9.3 footer replaces it), Cmd+, in `MetricPanel.keyDown`.
- `PreferencesStore.lastSettingsSection` (9.2), `CategoryIdentity` (9.1).

## Approach
1. **Core.** `Sources/iStatsCore/SettingsSection.swift`: `enum SettingsSection: Hashable, Sendable { case general, menuBar, category(MetricCategory), alerts, about }` with `storageKey`, `allSections(hasBattery:activeCategories:)`.
2. **Window.** `iStats/UI/Settings/SettingsView.swift` (new): `NavigationSplitView` sidebar (identity icons via `CategoryIdentity`) and detail. macOS 13 supports `NavigationSplitView`; use `.navigationSplitViewStyle(.balanced)`. Move existing pane contents as-is into detail views (`GeneralSettingsView`, `AlertsSettingsView` wrappers) so behaviour is unchanged.
3. **One window path.** `SettingsWindowController.shared.show(section:)` (new, replaces `PreferencesWindowController` usage); all openers call it; selecting an already-open window brings it front and switches section.
4. **Persistence.** Selected section written to `lastSettingsSection`; unknown or stale keys fall back to General.
