# Phase 9, task 9.7: Menu bar WidgetModel and renderer refactor

## Done

- Pure core `Sources/iStatsCore/WidgetModel.swift`: `WidgetModel` (text, fractions, color role, width class, series), `Hashable`, with `visualKey` as the single dirty-check and image-cache key. It replaces the `visualKeyFor*` family. `WidgetDescription.swift` holds the tooltip and accessibility strings.
- `iStats/UI/MenuBarIconRenderer.swift` cut from 3457 to 153 lines. Per-family renderers under `iStats/UI/MenuBar/` (Value, Dual, Bar, Ring, Graph, Glyph) behind the `WidgetRenderer` protocol and a `WidgetRenderers.draw` dispatcher. Renderer code total is now 1835 lines (153 + 1682).
- Deleted: the dead "Compatibility Drawings" block, the dead power-gauge code, `symbolImage(name:)`, all `render*`/`visualKeyFor*` functions and the sample-typed gauge/bar/sparkline wrappers.
- One constant for the thermal range (`WidgetModel.thermalRangeCelsius`, 30...100).
- Palette colors come from `CategoryPalette` (category, series and status colors), not `.systemX`.
- Each style has a fixed width class; `WidgetMetrics.width` measures the class worst case once.
- Graph models are stamp-based: a sparkline redraws only on a new sample, and its key is no longer nil.
- Minimum text size is 9 pt; the 5.8 pt stacked vertical labels are now a rotated 9 pt label.
- `MenuBarController.updateStatusItem` calls only `MenuBarIconRenderer.render(config:coordinator:preferences:)`.

Behavior changes to be aware of:

- Memory `.symbol` key now includes the ratio (the old key ignored it, so images went stale).
- Power `.text` is a plain two-line text ("92% ⚡" over "Charging") instead of the old `splitPrefixAndValue` output.
- Thermometer glyph width is fixed from the "212°F" worst case (3-digit values no longer widen it).
- 8.5 pt fonts became 9 pt, so some class widths grew by 1 to 2 pt: stacked text 33, two-line rate 61 or more, fan two-line and power two-line are measured from worst-case strings.
- GPU gauge no longer tints by temperature (color follows status level).
