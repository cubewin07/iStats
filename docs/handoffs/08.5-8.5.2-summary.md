# Summary — 8.5.2 Timestamped Telemetry Series & B8/B9 Fixes

## Done
- **Step 8.5.2.1 — `MetricsStore` Timestamped & Bucketed Queries (`Sources/iStatsCore/MetricsStore.swift`):**
  - Added `timedScalarHistory(for:duration:referenceDate:) -> [ChartPoint]` returning raw wall-clock-timestamped points within `(referenceDate - duration, referenceDate]`, cutting the window against the requested `referenceDate` rather than the newest stored sample (eliminates B8's 59–61 point window-count jitter). Existing `scalarHistory(for:duration:maxPoints:)` and `scalarTimeSpan(for:duration:)` keep their behavior for backward compatibility with existing callers/tests.
  - Added `bucketedScalarHistory(for:duration:bucketWidth:referenceDate:) -> [BucketPoint]` pre-filtering points to `t <= referenceDate` with whole-bucket cutoff (`bucketEnd > referenceDate - duration`) and delegating to `Downsampler.alignedBuckets` for immutable 5m (`2.5 s`) and 15m (`7.5 s`) envelope buckets.
  - Added `timedDualScalarHistory(primary:secondary:duration:referenceDate:) -> [DualChartPoint]` and `bucketedDualScalarHistory(primary:secondary:duration:bucketWidth:referenceDate:) -> (primary: [BucketPoint], secondary: [BucketPoint])` to query both channels against a single `referenceDate` and inner-join align by sample/epoch timestamp.
- **Step 8.5.2.2 — B9 Fix (`Sources/iStatsCore/MetricsStore.swift`):**
  - Added `ScalarSeriesKey.powerChargePercent` (12th scalar series, `+14,400` bytes / `~14.1 KB` for 900 `ScalarPoint`s).
  - Updated `recordScalarPoints(for:)` for `.power` so `powerDrawWatts` writes only to `.powerWatts` and `charge` writes only to `.powerChargePercent` (never writing battery charge percentage into `.powerWatts` when wattage is `nil`).
  - Updated `clear(category: .power)` to clear both `.powerWatts` and `.powerChargePercent`.
- **Step 8.5.2.3 — `MetricsCoordinator` Forwarding (`iStats/App/MetricsCoordinator.swift`):**
  - Exposed `timedScalarHistory(for:duration:referenceDate:)`, `bucketedScalarHistory(for:duration:bucketWidth:referenceDate:)`, `timedDualScalarHistory(primary:secondary:duration:referenceDate:)`, and `bucketedDualScalarHistory(primary:secondary:duration:bucketWidth:referenceDate:)`.
- **Step 8.5.2.4 — Unit Tests (`Tests/iStatsCoreTests/MetricsStoreTests.swift`):**
  - Updated `testScalarMemoryFootprintWithinBudget` for 12 scalar series (`172,800` bytes, `<= 175,000`).
  - Added `testTimedScalarHistoryPreservesTimestampsAndRequestedEdgeCutoff`, `testBucketedScalarHistoryStabilityAcrossAppends`, `testPowerWattsDoesNotStoreChargeWhenWattageNil_B9`, and `testDualChannelTimestampAlignment`.

## Audit: Full-Sample Ring vs. Scalar Buffer Mixing (for 8.5.5 / 8.5.8*)
Checked `MetricsCoordinator` and all files under `iStats/UI/Panels/`:
- `iStats/UI/Panels/NetworkPanel.swift` (`L118-119`): `deriveGlance` reads `coordinator.networkHistory` (60-sample full-sample ring) instead of scalar buffers (`.networkInBytesPerSec`, `.networkOutBytesPerSec`).
- `iStats/UI/Panels/DiskPanel.swift` (`L95-96`): `deriveGlance` reads `coordinator.diskHistory` (60-sample full-sample ring) instead of scalar buffers (`.diskReadBytesPerSec`, `.diskWriteBytesPerSec`).
- `iStats/UI/Panels/PowerPanel.swift` (`L96, L98, L126`): `deriveGlance` reads `coordinator.powerHistory` (60-sample full-sample ring) instead of `.powerChargePercent` / `.powerWatts` scalar buffers.
- `iStats/UI/Panels/HistoryPage.swift` (`L359, L396, L424, L449, L477, L504, L544, L582`): 1m (`!isExtended`) reads the 60-sample full-sample rings (`cpuHistory`, `memoryHistory`, `gpuHistory`, `thermalHistory`, `fanHistory`, `networkHistory`, `diskHistory`, `powerHistory`), while 5m/15m (`isExtended`) reads `coordinator.scalarHistory(...)`. (Note for 8.5.5: Thermal 1m also uses `thermalHistory` when a per-sensor `selectedThermalSource` filter is active, since `.thermalPeakCelsius` stores peak only.)
- `iStats/UI/Panels/PanelFactory.swift` (`L368`, inside dead `PanelHostView` slated for removal in 8.5.7): reads `.powerWatts` even on battery Macs; `L307-308` and `L338-339` also divide network/disk bytes/s by `1_000_000.0`.
- `CPUPanel`, `MemoryPanel`, `GPUPanel`, `TemperaturePanel`, and `FanPanel` already query `coordinator.scalarHistory` for their hero charts (and will migrate to `timedScalarHistory` / `timedDualScalarHistory` in 8.5.8*).
