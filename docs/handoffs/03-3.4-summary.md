# Summary — 3.4 Disk I/O throughput

## Done
- Implemented IOKit block storage statistics querying in `HostDiskInfoProvider` (`iStats/Sampling/DiskSampler.swift`):
  - Traversed `IOBlockStorageDriver` services in the IOKit registry via `IOServiceGetMatchingServices`.
  - Extracted and summed cumulative `Bytes (Read)`, `Bytes (Write)`, `Operations (Read)`, and `Operations (Write)` across all active block storage devices.
  - Properly managed IOKit lifecycle (`IOObjectRelease` on iterators and entries, CF ARC bridge ownership).
- Implemented Disk I/O rate calculation in `DiskSampler.swift`:
  - Defined `DiskIOState` tracking previous counter snapshot and timestamp.
  - Implemented `calculateIOSample` using pure `RateMath` to derive `bytesReadPerSec`, `bytesWrittenPerSec`, `readOpsPerSec`, and `writeOpsPerSec`.
  - Handled initial sample (0.0 rates) and counter resets / driver restarts (clamped to 0.0, never negative).
  - Graceful degradation: when IOKit statistics are inaccessible or fail, `DiskSample` is emitted with `io: nil` without blocking volume capacity reporting.
- Added comprehensive unit tests in `Tests/iStatsTests/DiskSamplerTests.swift`:
  - Initial cold-start sample test returning 0.0 I/O rates.
  - Multi-sample rate calculation test verifying accurate read/write byte throughput and ops throughput.
  - Counter reset and driver restart test (negative rate prevention and clamping to 0).
  - Graceful degradation test when I/O is unavailable or provider throws.
  - Zero/negative elapsed time step edge case testing.
  - Live host provider test against physical/VM macOS IOKit block storage devices.
