## 1. Summary of Changes

1. **Models & Pure Math (`ProcessRanking`):**
   - Added `ProcessInfoItem` and `ProcessSample` to `Sources/iStatsCore/Models.swift`.
   - Implemented `Sources/iStatsCore/ProcessRanking.swift`:
     - Calculates CPU % from $\Delta(\text{cpu time}) / \Delta(\text{wall}) \times 100$ adhering strictly to `RateMath` invariants (counter resets and PID reuses yield 0.0, never negative spikes).
     - Aggregates helpers and XPC children under common application bundle IDs.
     - Deterministic tie-breaking by PID for both `.cpu` and `.memory` criteria.
     - Verified by 6 comprehensive unit tests in `Tests/iStatsCoreTests/ProcessRankingTests.swift` (6/6 passed).

2. **Background Sampling Layer (`ProcessSampler`):**
   - Implemented `iStats/Sampling/ProcessSampler.swift`:
     - Uses `proc_listpids` and `proc_pid_rusage(RUSAGE_INFO_V4)` to extract `ri_user_time + ri_system_time` and `ri_phys_footprint`.
     - Maps GUI application bundle IDs and friendly names via `NSWorkspace.shared.runningApplications` with fallback to `proc_name`.
     - Skips unprivileged system daemons (EPERM) silently without privilege escalation (ADR 0004/0005).

3. **Demand-Driven Coordinator Lifecycle:**
   - Updated `iStats/App/MetricsCoordinator.swift` with `startProcessDemand()` and `stopProcessDemand()`.
   - Runs on a detached utility background task only while consumer count > 0; terminates immediately when panels close, incurring **0% background CPU overhead** at idle.

4. **UI Presentation (`TopConsumersModule`):**
   - Implemented `iStats/UI/Instrument/Kit/TopConsumersModule.swift`:
     - Cached 16×16 pt app icon loader (`ProcessIconCache` on MainActor) with gearshape fallback.
     - Up to 5 ranked rows with process name, micro-sparkline of the last 30 samples, and formatted value (% for CPU, bytes for Memory).
     - Header dynamic title: "Top Processes" or "Your Apps" if any unprivileged PIDs were skipped.
     - Action affordance button to launch macOS Activity Monitor.

5. **Panel Integration:**
   - Integrated `TopConsumersModule` into `CPUPanel.swift` (CPU % sorting + micro-sparkline) and `MemoryPanel.swift` (physical footprint sorting).
   - Hooked up `.onAppear { coordinator.startProcessDemand() }` and `.onDisappear { coordinator.stopProcessDemand() }` on both panels.

6. **Testing:**
   - Added `Tests/iStatsTests/ProcessSamplerTests.swift` verifying live sampling, non-empty memory rankings, and demand-driven lifecycle cleanup.
