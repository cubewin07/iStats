## 1. What was built

Implemented the dedicated CPU Instrument panel following the design specification (`design.md §6.1` / ADR 0009):

- `iStats/UI/Panels/CPUPanel.swift`:
  - **Glance Header:** Aggregate `totalUsage` (44 pt `LiveNumber`), `PanelHeadline.cpu` diagnostic copy ("Moderate load · 10 cores · 3.2 GHz"), `.stacked(primary: user, secondary: system)` hero `LiveChart`, trailing `InsightEngine` telemetry summary.
  - **Now Page (Signature Instrument):**
    - *Core Map:* Dual `ClusterStrip` instances for Performance (P) and Efficiency (E) core clusters with leading average labels (`P · 62%` / `E · 18%`), or a unified strip for non-hybrid / Intel topologies. Dynamic hover updates the eyebrow slot with real-time per-core inspection (e.g. "Core 4 (P) · 81%").
    - *Load Average Module:* 1m, 5m, 15m load metrics with an automatic quiet status dot that illuminates only if 1m load exceeds available core capacity.
  - **Detail Page (Cores):**
    - User / System / Idle `SplitCapsule` composition with proportional `SegmentLayout` widths and legend readout.
    - Per-core metric rows showing core index, utilization, critical/elevated status, and in-memory 60-sample micro-sparklines.
    - System uptime row formatted via `Units.formatUptime`.
  - **History Page:**
    - Active 60s buffer metrics and user peak utilization.

- `iStats/App/MetricsCoordinator.swift`:
  - Added `@Published public private(set) var coreHistory: [Int: [Double]] = [:]` retaining up to 60 telemetry samples per core in memory only (ADR 0006 compliance).

- `iStats/UI/Panels/PanelFactory.swift`:
  - Wired `CPUPanel` as the dedicated renderer for `.cpu`.
