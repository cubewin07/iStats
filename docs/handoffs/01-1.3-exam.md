# Exam — 1.3 Define core protocols and value types

## Snapshot
On disk today in `Sources/iStatsCore/`:
- `Availability.swift`: defines `Availability` (`.available`, `.unavailable(reason:)`) and generic `Sample<Value: Sendable>`.
- `MetricCategory.swift`: defines `MetricCategory` (`cpu`, `memory`, `thermal`, `fan`, `gpu`, `network`, `disk`, `power`) and `displayName`.
- `Sampler.swift`: defines `protocol Sampler: Sendable` with `associatedtype Output: Sendable`, `category: MetricCategory`, `sample() throws -> Output`, and `SamplerError` (`unsupported`, `systemCallFailed`, `timedOut`).
- `Models.swift`: defines leaf types `CPUSample`, `MemoryPressure`, `MemorySample`, `SensorReading`, `FanReading`, `InterfaceThroughput`.
- Missing in `Models.swift`: composite sample wrappers explicitly listed in `docs/progress.md` and phase designs (`ThermalSample`, `ThermalPressure`, `FanSample`, `NetworkSample`, `VolumeCapacity`, `DiskIO`, `DiskSample`, `BatteryState`, `PowerSample`, `GPUSample`).
- Missing tests: `Tests/iStatsCoreTests/` currently only tests `RateMathTests`, `RingBufferTests`, and `UnitsTests`. No dedicated unit tests exist for `Availability`, `Sample<T>`, `MetricCategory`, `Sampler`, or `Models`.
