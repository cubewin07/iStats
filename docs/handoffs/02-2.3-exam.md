# Exam — 2.3 Property tests for CPU % math

## Snapshot
- `Sources/iStatsCore/RateMath.swift` contains pure math helpers: `cpuUsagePercent(busyDelta:totalDelta:)`, `counterDelta(previous:current:)`, `bytesPerSecond(previous:current:elapsedSeconds:)`.
- `iStats/Sampling/CPUSampler.swift` contains `ProcessorTicks`, `CPUInfoProvider`, `HostProcessorInfoProvider`, and `CPUSampler` with pure `calculateSample(previous:current:loadAverage:frequencyHz:)`.
- `Tests/iStatsCoreTests/RateMathTests.swift` contains 12 unit tests covering basic scenarios and a basic bound property.
- `Tests/iStatsTests/CPUSamplerTests.swift` contains 6 tests covering baseline, rate calculation, counter wrapping, topology change, error handling, and live host processor info provider.

## Risks and unknowns
- Floating-point rounding tolerances when summing `user + system + idle`: with `Double`, accuracy threshold `1e-5` to `1e-9` is appropriate.
- When `totalDelta == 0` (no elapsed ticks), `user`, `system`, and `idle` must all be `0.0`, rather than `NaN` or dividing by zero.
- Counter wrap cases on a subset of cores: if one core wraps while other cores advance, total usage and unaffected cores must still compute cleanly.
