# Summary — 9.8 Widget Catalog Consolidation and Appearance Modes

## Done
- **Widget catalog consolidation (`Sources/iStatsCore/MenuBarItemConfig.swift`, `Sources/iStatsCore/WidgetCatalog.swift`)**:
  - Aligned `MetricDisplayStyle` to the shared 6-family vocabulary (`Value`, `Dual`, `Bar`, `Ring`, `Graph`, `Glyph`) with `widgetFamily`, `vocabularyName`, and source-compatible static aliases (`.value`, `.dual`, `.ring`, `.graph`, `.symbol`).
  - Collapsed Temperature's five legacy per-sensor cases (`cpuTemp`, `gpuTemp`, `memoryTemp`, `storageTemp`, `batteryTemp`) into `.text` (Value) with a `source: MetricSource` option.
  - Removed the overloaded `.throughput` style from Fan and Power (`supportedStyles` now returns 4 styles for Fan and 3 battery / 2 desktop styles for Power) and eliminated duplicate rings/bars.
  - Added an explicit deterministic legacy raw-value migration map (`MenuBarItemConfig.migratedStyle(for:rawStyle:source:)`) covering every historical style string across every category so persisted configs migrate cleanly without silently dropping items.
  - Added `WidgetCatalogEntry` and `WidgetCatalog` (`entries(for:hasBattery:)`, `defaultEntry(for:hasBattery:)`, `allEntries(hasBattery:)`, `entry(for:style:hasBattery:)`) with deterministic `sampleSnapshot(hasBattery:)` builders. Guarded with `WidgetCatalogTests` ensuring catalog entries exactly match `supportedStyles` and hide battery-only entries when `!hasBattery`.
- **Hardware-aware presets (`Sources/iStatsCore/MenuBarPreset.swift`)**:
  - Added `MenuBarPreset` (`.minimal`, `.balanced`, `.everything`) with `configs(hasBattery:hasFans:)` and `items(for:hasBattery:hasFans:)`.
  - Omits Battery widgets when `!hasBattery` and Fan widgets when `!hasFans`; keeps `.balanced` identical to `MenuBarItemConfig.defaultConfigs()`.
- **Menu bar appearance modes (`Sources/iStatsCore/WidgetModel.swift`, `iStats/UI/MenuBarIconRenderer.swift`, `iStats/UI/MenuBar/*.swift`, `iStats/App/MenuBarController.swift`)**:
  - Wired `PreferencesStore.menuBarAppearance` (`.monochrome`, `.statusTint` default, `.categoryColor`) through `WidgetOptions`, `WidgetModel.appearance`, `WidgetModel.colorRole`, and `WidgetModel.visualKey`.
  - Updated all six per-family renderers (`ValueWidget`, `DualWidget`, `BarWidget`, `RingWidget`, `GraphWidget`, `GlyphWidget`) so `.monochrome` emits template images (`isTemplate = true`), `.statusTint` stays template until `.warning`/`.critical` and then tints with `CategoryPalette.statusNSColor`, and `.categoryColor` uses `CategoryPalette` category/series accents.
  - Subscribed `MenuBarController` to `preferences.$menuBarAppearance` so changing appearance immediately invalidates render state and redraws active status items.
- **Widget previews and catalog UI (`iStats/UI/MenuBar/WidgetPreview.swift`, `iStats/UI/Settings/WidgetCatalogView.swift`)**:
  - Added `WidgetPreviewRenderer` and `WidgetPreview` rendering `WidgetModel` / `WidgetCatalogEntry` / `MenuBarItemConfig` at 1x/2x scale while honoring `MenuBarAppearance` and light/dark `NSAppearance`.
  - Added `WidgetCatalogView` displaying a category's widget catalog grid with live/sample previews, Add/Replace/Remove actions, sensor source / dual layout / label options, and a segmented control bound to `PreferencesStore.menuBarAppearance` (ready for Task 9.10 to host in Settings).
- **Status item right-click context menu (`iStats/App/MenuBarController.swift`)**:
  - Updated the status item context menu via `makeContextMenu(for:)` with: **Show Overview** (with `onShowOverview` hook + `Notification.Name("iStats.showOverview")` and `lastPanelDestination = .overview`), **Settings for \<Category\>…** (calls `PreferencesWindowController.shared.showPreferences()` then posts `Notification.Name("iStats.openSettingsSection")` with `userInfo: ["section": category.rawValue]`), **Hide This Widget**, **Pause Sampling** / **Resume Sampling**, and **Quit iStats**.
