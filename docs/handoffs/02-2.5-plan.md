# Plan — 2.5 Memory pressure level + UI surfacing

## Intent
Implement real-time Darwin memory pressure monitoring via `DispatchSourceMemoryPressure` and `sysctl`, and surface memory pressure levels (normal, warning, critical) visibly in the UI with distinct styling and alert banners per Requirement 2.4.

## Current code
- `Sources/iStatsCore/Models.swift`: `MemoryPressure` enum (`normal`, `warning`, `critical`).
- `iStats/Sampling/MemorySampler.swift`: `HostMemoryInfoProvider` queries `kern.memorystatus_vm_pressure_level`.
- `iStats/UI/DetailPopoverView.swift`: Base popover shell.

## Approach
1. Add extensions to `MemoryPressure` in `Sources/iStatsCore/Models.swift` (`displayName`, `isElevated`, `severityRank`).
2. Create `iStats/Sampling/MemoryPressureMonitor.swift`:
   - Dedicated `DispatchSourceMemoryPressure` listener managing kernel pressure event stream on a background queue.
   - Thread-safe storage of latest `MemoryPressure`.
   - Update `HostMemoryInfoProvider` to incorporate `MemoryPressureMonitor.shared.currentPressure`.
3. Create `iStats/UI/MemoryPressureView.swift`:
   - `MemoryPressureBadgeView`: Visual badge/tag showing pressure status with color-coded dot/icon (green for normal, amber/yellow for warning, red for critical).
   - `MemoryPressureAlertBanner`: Prominent banner rendered when pressure is in warning or critical state.
   - `MemorySummaryView`: Section displaying memory breakdown (used, free, cached, wired, swap) along with the pressure level.
4. Update `DetailPopoverView.swift` to incorporate memory stats and the prominent memory pressure alert banner when elevated.
5. Create `Tests/iStatsTests/MemoryPressureTests.swift` testing memory pressure transitions, monitoring events, and UI state models.
6. Register new files in `iStats.xcodeproj/project.pbxproj`.
7. Verify all test suites and Xcode builds.
