# Summary — 2.5 Memory pressure level + UI surfacing

## Done
- Enhanced `MemoryPressure` in `Sources/iStatsCore/Models.swift`:
  - Added `displayName` ("Normal", "Warning", "Critical").
  - Added `isElevated` (`true` if warning or critical).
  - Added `severityRank` and `Comparable` conformance (`.normal < .warning < .critical`).
- Implemented `iStats/Sampling/MemoryPressureMonitor.swift`:
  - Background `DispatchSourceMemoryPressure` event listener on a dedicated queue (`com.istats.memorypressure`, `.utility` QoS).
  - Thread-safe tracking of current kernel memory pressure state.
  - Event mapping and listener subscription mechanism for immediate notifications on pressure changes.
- Integrated `MemoryPressureMonitor` into `HostMemoryInfoProvider.memoryPressure()` in `iStats/Sampling/MemorySampler.swift`.
- Implemented SwiftUI memory pressure and summary UI components in `iStats/UI/MemoryPressureView.swift`:
  - `MemoryPressureBadgeView`: Visual badge with distinct iconography and colors (green for normal, orange for warning, red for critical).
  - `MemoryPressureAlertBanner`: Prominent high-visibility warning and critical alert banner shown when pressure is elevated (Requirement 2.4).
  - `MemorySummaryView`: Complete memory card showing used vs total gauge, memory breakdown grid (wired, compressed, cached, swap used), pressure badge, and alert banner.
- Updated `DetailPopoverView.swift` in `iStats/UI/DetailPopoverView.swift` to render `MemorySummaryView` with live memory telemetry and asynchronous off-main-thread sampling.
- Created `Tests/iStatsTests/MemoryPressureTests.swift`:
  - Unit tests for `MemoryPressure` properties, ranking, and comparisons.
  - DispatchSource event mapping assertions.
  - `MemoryPressureMonitor` update broadcasts and listener callbacks.
  - Thread safety and idempotency tests.
  - SwiftUI view rendering tests for normal, warning, and critical states.
- Updated `iStats.xcodeproj/project.pbxproj` with valid, non-colliding PBX file references and build targets.
