# Plan — 2.1 Implement CPUSampler (total + per-core)

## Goal
Implement `CPUSampler` using Mach `host_processor_info(PROCESSOR_CPU_LOAD_INFO)` to read per-core cumulative CPU tick counters, track previous snapshot, and compute total and per-core utilization percentages, breaking down user, system, and idle time.

## Proposed Changes

### 1. `Sources/iStatsCore/RateMath.swift`
- Add `counterDelta(previous: UInt64, current: UInt64) -> UInt64` helper.
- Ensure counter reset / wrap returns 0 to prevent negative rate spikes (Invariant 3).

### 2. `iStats/Sampling/CPUSampler.swift`
- Model `ProcessorTicks` holding `user`, `system`, `idle`, `nice` tick counts.
- Protocol `CPUInfoProvider` and default `HostProcessorInfoProvider` invoking `host_processor_info`.
- Safely check `kern_return_t` and non-null pointers, `defer` deallocating via `vm_deallocate`.
- Class `CPUSampler: Sampler, @unchecked Sendable` (`Output = CPUSample`, `category = .cpu`).
- Thread-safe state tracking for previous snapshot using `NSLock`.
- Pure method `calculateSample(previous: [ProcessorTicks]?, current: [ProcessorTicks]) -> CPUSample` computing aggregate %, per-core % array, user %, system % (with nice), and idle %.

### 3. Unit Tests
- Add `RateMathTests` cases for `counterDelta`.
- Add `CPUSamplerTests` testing:
  - First sample returns 0% (graceful cold-start).
  - Normal multi-core sample calculation with synthetic ticks.
  - Counter wrap/reset handling.
  - Real hardware sampling via `HostProcessorInfoProvider`.

### 4. Project Configuration & Progress
- Add `iStats/Sampling` to `iStats.xcodeproj`.
