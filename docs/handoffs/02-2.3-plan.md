# Plan — 2.3 Property tests for CPU % math

## Intent
Add comprehensive, hardware-independent property-based and parameterized unit tests for CPU % math and sample calculation (`RateMath` and `CPUSampler.calculateSample`). These tests verify that across all synthetic tick inputs (monotonic sequences, counter wraps, extreme magnitudes, multicore topologies, asymmetric workloads, and randomized synthetic counters):
1. All utilization outputs (`totalUsage`, `perCore`, `user`, `system`, `idle`) strictly fall within `0.0...100.0`.
2. Monotonic non-decreasing counters never produce negative numbers or negative rates.
3. Breakdown percentages (`user + system + idle`) reconcile to 100% when total delta > 0, and reconcile to `totalUsage` (where `user + system == totalUsage`).
4. Zero elapsed delta or initial sample safely produces 0.0% without NaN, crash, or division by zero.
5. Counter wraps or resets on any combination of cores clamp safely to 0 delta without underflows or corrupting other cores.

## Current code
- `Sources/iStatsCore/RateMath.swift`: Pure math functions for rates and counter deltas.
- `iStats/Sampling/CPUSampler.swift`: Contains `calculateSample(previous:current:loadAverage:frequencyHz:)`.
- `Tests/iStatsCoreTests/RateMathTests.swift`: Existing pure tests in `iStatsCoreTests`.
- `Tests/iStatsTests/CPUSamplerTests.swift`: Existing CPU sampler tests in `iStatsTests`.

## Approach
1. **Extend `Tests/iStatsCoreTests/RateMathTests.swift`**:
   - Add property tests for `RateMath.cpuUsagePercent`:
     - Invariant: Bounded in `0.0...100.0` for all positive, negative, zero, and extreme float inputs.
     - Invariant: Monotonicity with respect to `busyDelta` for constant `totalDelta > 0`.
     - Invariant: Additivity / reconciliation (`cpuUsagePercent(busyDelta: a + b, totalDelta: T) == cpuUsagePercent(a, T) + cpuUsagePercent(b, T)` when `a + b <= T`).
   - Add property tests for `RateMath.counterDelta`:
     - Monotonic sequence always produces exact difference `c - p`.
     - Decreasing sequence (wrap/reset) always produces `0`.
     - Identity `counterDelta(p, p) == 0`.
     - Large values near `UInt64.max`.
2. **Extend `Tests/iStatsTests/CPUSamplerTests.swift`**:
   - Add dedicated property-based testing functions for `CPUSampler.calculateSample`:
     - `testPropertyBoundsInvariantAcrossSyntheticScenarios`: Tests `0...100` bounds on total, per-core, user, system, idle across hundreds of synthesized multi-core states.
     - `testPropertyReconciliationInvariant`: Tests `user + system + idle == 100.0` and `user + system == totalUsage` for non-zero elapsed ticks.
     - `testPropertyZeroElapsedTicksProducesZeroUtilization`: Tests that when counters do not change, all utilization metrics return `0.0`.
     - `testPropertyMonotonicity`: Incremental work increases or preserves utilization.
     - `testPropertyCounterWrapOnCoreSubsets`: Verifies independent core isolation when 1 core wraps while others increment.
     - `testPropertyExtremeValuesNearUInt64Max`: Verifies safety with huge tick counts near `UInt64.max`.
     - `testPropertyAsymmetricMulticoreLoads`: Verifies weighted average reconciliation on multicore topologies (1 to 64 cores) with uneven tick distributions.
     - `testPropertyFuzzRandomizedSyntheticTicks`: Deterministic PRNG generated fuzzing with 1,000+ random transitions testing all invariants simultaneously.
