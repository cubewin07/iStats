# Plan — Premium, smooth popovers (Phase 8.5, amended)

## Context

The Phase 8 "Instrument" panels look unfinished and misbehave. A full spec for the fix already exists and is accepted but unbuilt: Phase 8.5 (`docs/phases/phase-08.5-instrument-polish/`, ADR 0010), next task 8.5.1. I read every file in the popover path and confirmed its 13 animation defects (A1–A13) in code.

I also found **14 bugs the 8.5 spec does not cover** (B1–B14 below). Several of them are the most visible ones, and none depend on the new chart engine.

**Recommendation:** execute Phase 8.5 as specified, with two amendments:
1. Add the B-list to the spec.
2. Split task 8.5.6 so the shell correctness fixes land **first**, before the chart engine. ADR 0010 locked the order chart → shell; this reorders it, because B1–B6 are what makes the popovers feel broken today.

No new visual language is invented here. `design.md` §2–§4 stays the canonical look.

## Bugs found beyond A1–A13

| ID | Bug | Where |
|----|-----|-------|
| **B1** | Clicking a different widget while a panel is open makes the panel vanish. The local mouse-down monitor starts `close()` (0.12 s fade), mouse-up calls `show()`, which reuses the still-visible fading panel and skips the fade-in; the close teardown then `orderOut`s it while state says "open". | `PanelController.close/show` + monitors `:115–147, :385–403` |
| **B2** | Window height only updates on first appear and on tab change. Any other height change clips content or leaves a gap: top-processes list filling in, status ribbon appearing, "Show all interfaces", pause toggle. | `PanelScaffold.swift:445–456` |
| **B3** | The Now page never scrolls. Content taller than the 560 pt cap is cut off (CPU on many-core Macs, Temperature). | `PanelScaffold.swift:420–421` |
| **B4** | Details/History use `ViewThatFits`, which builds the page twice and can flip between plain and scrolling layout while the window animates. | `PanelScaffold.swift:423–441` |
| **B5** | First open measures `fittingSize` before layout, then corrects asynchronously — visible height jump on open. | `PanelController.reposition :319–322` |
| **B6** | Hover-scrubbing onto a widget whose category is already pinned opens a second, transient panel for it. Keyboard commands hit both, and the transient shows a close button that closes the pinned one. | `PanelController.handleStatusItemHover :176–187` |
| **B7** | On a flat series (idle network, steady memory, stopped fan) the chart glides and snaps back every second forever: the glide clock only resets when values *change*. | `LiveChart.swift:224–226` |
| **B8** | The hero chart's point count fluctuates 59–61 because the 60 s window is cut relative to the newest sample, so the curve's horizontal scale jitters. Panels also mix two history sources (scalar buffer vs full-sample ring), so 1m and 5m History disagree. | `MetricsStore.scalarHistory :375–392`, panel `deriveGlance`s |
| **B9** | The `powerWatts` series stores battery **percent** whenever wattage is missing — watts and percent mixed in one line. | `MetricsStore.swift:126–131` |
| **B10** | History range is loaded in `onAppear`, so the page draws 1m then flips to the saved range. Tap-to-scrub on a stat cell freezes the chart on a fixed index that drifts as samples arrive. | `HistoryPage.swift:96–98, :291–302` |
| **B11** | Every row hover-highlights and is click-to-copy by default, including labels like "Read-only (ADR 0004)". Crosshair dots use a hardcoded white ring (wrong in Light mode). | `MetricRow.swift:27`, `LiveChart.swift:933, :997` |
| **B12** | Process icons for non-app processes are looked up on the main thread on every render (misses are never cached). | `TopConsumersModule.swift:13–23` |
| **B13** | Fan "Details" renders the same page as "Now". Memory shows a fabricated 25/65/95 gauge (already in 8.5.8b). | `FanPanel.swift:69–70` |
| **B14** | Each panel re-derives its glance (history copy, filter, downsample, insight) on every coordinator publish; `PanelHostView` is dead code that does it three times. | all `*Panel.deriveGlance`, `PanelFactory.swift:110–498` |

Each task: own commit, tests green, `docs/progress.md` row updated. Phase-plan checkboxes stay untouched.

- Split `tasks/8.5.6-…md` into **8.5.6a** (shell lifecycle and sizing, no dependencies, runs first) and **8.5.6b** (header v2, text switcher, status chip; still after 8.5.4). Register both in `tasks.md` and `docs/progress.md`.

### Stage 1 — 8.5.6a Shell lifecycle and sizing (fixes B1–B6, A10, A11)
Files: `iStats/App/MetricPanel.swift`, `iStats/App/PanelController.swift`, `iStats/UI/Panels/PanelScaffold.swift`, `iStats/App/MenuBarController.swift`.

- **Persistent host.** `MetricPanel` creates one `PanelBackgroundView` + one `NSHostingView<AnyView>` in `init`, with `sizingOptions = []` so Auto Layout never fights the animated frame. `setSwiftUIContent` only swaps `rootView`. On close, set the root to `EmptyView` so timelines stop and `onDisappear` fires (keeps `startProcessDemand`/`stopProcessDemand` balanced).
- **One height channel.** A `PanelContentHeightKey` preference on the scaffold's top-aligned root reports height; `MetricPanel` forwards it to `PanelController.setContentHeight(_:for:animated:)`, which does the top-anchored `setFrame` (0.32 s, control points `0.2, 0.9, 0.25, 1.0`). Delete both `DispatchQueue.main.async { updateFittingHeight }` calls and the `fittingSize` reads. This fixes every case in B2 at once.
- **First-open size.** Measure with `NSHostingController.sizeThatFits(in:)` (macOS 13, the deployment target) before ordering front, so the panel opens at its final height.
- **One scroll container.** Replace `ViewThatFits` with a single `ScrollView` around the page body for all three tabs; its height is `min(measuredBodyHeight, maxHeight − chromeHeight)`, scrolling disabled when it fits. Body built once.
- **Close/show race.** Add a transition generation counter: `show()` during a fade-out bumps it, animates alpha back to 1, and the stale teardown returns early. The dismissal monitors ignore clicks on any of the app's status-item buttons (inject a hit-test closure from `MenuBarController`) so `toggle` alone decides.
- **Pinned guard.** `show`/`handleStatusItemHover` for a category with a visible pinned panel closes the transient and fronts the pinned one, like `toggle` already does.
- **Remove** the cross-view `matchedGeometryEffect` between hero chart and History chart; hero chart collapses, History fades/slides in 8 pt.
- Pin/unpin: animate the move to the saved origin; fade out on unpin.

Tests: extend `PanelPlacementTests`; new `PanelControllerLifecycleTests` in `Tests/iStatsTests` (show-during-close keeps the panel visible; hover onto pinned category creates no transient; height preference resizes top-anchored and clamps to screen); update `PanelScaffoldTests`.

### Stage 2 — Chart engine (8.5.1 → 8.5.5 as specified, plus B7–B10)
- **8.5.1** `ChartTimeline`, `ChartScale`, `Downsampler.alignedBuckets` in `Sources/iStatsCore/` with unit tests. Reuse `LiveChartMath.smoothSegments` and `niceTicks` — do not rewrite the spline.
- **8.5.2** Timestamped queries on `MetricsStore`/`MetricsCoordinator`. Window is cut against the *requested* edge, not the newest sample (B8). All panels and `HistoryPage` read the scalar buffers only. Stop writing charge into `powerWatts`; add a `powerChargePercent` key (B9; +14 KB, update the `MetricsStoreTests` footprint assertion).
- **8.5.3** `LiveChart` v3 in `iStats/UI/Instrument/LiveChart.swift`: time-domain x, delayed edge follower driven by sample timestamps rather than value changes (B7), independent mirrored scales, calm head bead, dark-mode bloom. Collapse the four near-identical series renderers into one path builder.
- **8.5.4** `ChartScrubState` header readout; crosshair v2 with a surface-coloured ring (B11).
- **8.5.5** `HistoryPage` v3. Initialise `selectedRange` from preferences in `init`; stat-cell scrub pins a **timestamp**, not an index (B10).
