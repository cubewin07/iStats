# Exam — 2.6 Render CPU + memory in the detail view

## Snapshot
- `Sources/iStatsCore/`:
  - `Models.swift`: `CPUSample`, `LoadAverage`, `MemorySample`, `MemoryPressure` exist.
  - `MetricsStore.swift`: Ring buffer store with `cpuHistory()` and `memoryHistory()` accessors exists.
  - `SampleScheduler.swift`: Background sampling scheduler with per-sampler isolation and interval management exists.
  - `PreferencesStore.swift`: Manages `refreshInterval`, `enabledCategories`, display units, and Dock icon; currently missing `menuBarDisplayMode` for Requirement 9.4.
- `iStats/Sampling/`:
  - `CPUSampler.swift`: Background CPU sampler calculating aggregate, per-core, user/sys/idle, load average, and frequency.
  - `MemorySampler.swift`: Background Memory sampler calculating RAM breakdown and memory pressure.
- `iStats/App/`:
  - `MenuBarController.swift`: Manages `NSStatusItem` and popover; currently renders static icon only.
  - `AppDelegate.swift`: Instantiates `MenuBarController` and applies dock icon policy.
- `iStats/UI/`:
  - `DetailPopoverView.swift`: Displays static header and memory summary; missing CPU summary, per-core breakdown, live rolling graphs, and dynamic live updates via scheduler.
  - `MemoryPressureView.swift`: `MemorySummaryView` displays memory breakdown and pressure badge/alert banner; missing rolling history graph.
  - `PreferencesView.swift`: Displays preferences tabs; missing menu bar metric selector.

## Risks and unknowns
- Graph rendering performance: SwiftUI `Path` / `Canvas` must be lightweight and allocate zero memory during redraws.
- Per-core UI scaling: Systems with 8 to 24+ cores should layout cleanly in a multi-column compact matrix.
- Menu bar text sizing: Status item title changes must resize smoothly without clipping or jitter.
